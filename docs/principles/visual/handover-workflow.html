Device handover workflow

How to read this page

Follow numbered steps in order. A dependency means every prerequisite must be passed or skipped before its dependent step runs. Select a step to inspect rules and neighbors. A pencil marks a write to Snipe-IT; a target marks a read or confirmation.

Stage statuses from code: pending, passed, failed, blocked, skipped. Status always has a text label.

4. Failure and recovery paths

Dashed red branches indicate a failure; the next action is stated beside it.

✕

device_prepared

Device is damaged or not ready

Next: Resolve the physical issue, then confirm preparation.

✕

user_signed_in

Employee cannot sign in

Next: Check network/identity access and confirm the employee reaches the desktop.

✕

agent_report

Agent report missing or serial/hardware invalid

Next: Run the agent again and resolve the reported mismatch.

✕

software_check

Required software missing or Windows not activated

Next: Install or activate, then re-evaluate; any override needs a reason.

✕

recipient_check

Recipient not found in Snipe-IT

Next: Check the identity and ask an asset administrator to correct Snipe-IT.

✕

checkout

Checkout verification does not match

Next: Refresh the asset state and resolve the current holder before retrying.

✕

report_printed

Report did not print

Next: Check the selected printer and print the report page again.

✕

user_signed

Signed sheet was not returned

Next: Ask the employee to sign the printed sheet before scanning.

✕

document_scanned

Wrong file type or upload exceeds the limit

Next: Rescan to a supported file type and upload again.

✕

document_pushed

Push was not verified

Next: Check the asset exists and verify the attachment before retrying.

5. Case lifecycle

Lifecycle names are read from HandoverStatus. Derivation follows derive_status.

Statuses in code: draft, in_progress, stalled, completed, cancelled

  1. draft — All stages pending and below the age threshold.
  2. in_progress — At least one stage has activity; no failure, block, completion, cancellation, or age stall.
  3. stalled — Any stage failed/blocked, or inactive longer than STALL_HOURS (default 24; zero disables).
  4. completed — Every stage is passed or skipped.
  5. cancelled — Explicit cancellation; this status takes precedence.
