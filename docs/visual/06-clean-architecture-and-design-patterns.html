Layers and the dependency rule

RuleText
ARC-01app/domain/*: pure Python, standard library only. No I/O, no framework imports, no clock reads (time is passed in).
ARC-02app/repositories/*: the main place reusable queries are written. They return model objects or small DTOs, never expose sessions to callers above services. Recorded exception: the read-only dashboard aggregates in app/services/dashboard.py build their SQLAlchemy select/func expressions directly on the injected session because they are a single read-only reporting use case; they never write and never leak the session. Moving them into a repository is a future refactor, not a hidden rule.
ARC-03app/clients/*: the only place external HTTP is spoken. They translate external responses and errors into typed results and typed exceptions.
ARC-04app/services/*: orchestration, idempotency, verification, transactions. No fastapi imports, no HTTP status codes (raise domain/service exceptions; routers map them).
ARC-05app/routers/*: parse input, enforce authentication, call exactly one service operation, return a DTO. No business logic, no direct DB or httpx.
ARC-06app/dto/*: pydantic request/response models. Database models are never returned directly.
ARC-07app/config.py is the only reader of environment variables.
ARC-08tests/test_architecture_rules.py enforces ARC-01, 04, 05 automatically. tests/test_graph_consistency.py keeps the module/route graph honest. Security middleware is tested separately in tests/test_security_hardening.py.
ARC-20app/security/* is a cross-cutting infrastructure package: startup validation, CSRF/Origin, headers and the in-memory limiter. It may import app/config.py; routers and services must not depend on it for business behavior.

Patterns to use (and only where they earn their place)

RuleText
ARC-09Repository: data access for handovers and events.
ARC-10Adapter/Client: SnipeItClient hides Snipe-IT's wire format.
ARC-11Strategy/Provider: SnipeItCredentialProvider so the token source can change later without touching services.
ARC-12State machine via pure functions: stage ordering, can_run, derive_status live in the domain.
ARC-21Hardware and software evidence evaluation lives in pure app/domain/software_rules.py; app/services/software_check.py coordinates the persisted override and reevaluation.
ARC-13Dependency injection through FastAPI Depends and constructor arguments; tests override them.
ARC-14Unit of work: one request, one database session, commit in a single place (get_session).
4

Patterns to avoid

RuleText
ARC-15No generic base repositories, no abstract factories, no event buses, no plugin systems, no premature configurability. Add abstraction only when a second concrete need exists.
5

Database sessions (async)

RuleText
ARC-16expire_on_commit=False. No lazy loading: load what you need explicitly (selectinload). No ORM objects used after the session closes.
ARC-17The engine is created lazily; importing the app never opens a database connection (the characterization tests depend on this).
ARC-18Schema changes only through Alembic migrations. No create_all in application code.
6

Compatibility

RuleText
ARC-19Existing endpoints keep their paths and response shapes. New behavior is added through new endpoints or optional parameters whose default preserves current behavior.
