## What you will have at the end

The Handover Portal runs locally on your Windows PC. Snipe-IT is an optional separate local development instance. For real employee devices, use a reachable internal address and approved HTTPS deployment.

| Component | Address | Who uses it |
|---|---|---|
| Handover Portal | `http://localhost:8080` | IT engineer |
| Snipe-IT development instance | `http://localhost:8081` | IT engineer and portal API |
| Device agent | Downloaded from the portal | Employee device; reports to the portal |

## Part 1: Get the code from GitHub

The repository is `https://github.com/adelromany/auto-check-asset-management.git`. Clone branch `docs/deployment-guide`, which contains this guide. This branch is local and must be published to GitHub before a clean PC can clone it. Ask the repository owner to publish it if it is not listed on GitHub.

1. Choose a working folder and clone the branch.

   ```powershell
   Set-Location $env:USERPROFILE\source
   git clone https://github.com/adelromany/auto-check-asset-management.git --branch docs/deployment-guide
   Set-Location .\auto-check-asset-management
   ```

   This downloads the repository. You should see `Cloning into` and the prompt at the repository folder. This command is **NOT VERIFIED** against GitHub because the branch has not been published.

2. Confirm the checked out commit.

   ```powershell
   git log -1 --oneline
   ```

   You should see the latest commit on `docs/deployment-guide`.

3. Update the local copy later.

   ```powershell
   git pull
   ```

   You should see `Already up to date` or a list of updated files.

## Part 2: Install the portal

1. Create the virtual environment, install Python packages, create `.env`, and apply migrations.

   ```powershell
   .\scripts\setup.ps1
   ```

   The script creates `.venv`, installs `requirements.txt`, creates `.env` with a random session secret if needed, and runs `alembic upgrade head`. It does not display the secret. You should see `Portal setup complete`.

2. Review `.env` in a text editor. Do not paste secret values into chat or logs. `.env` and `deploy/snipeit-dev/.env` are ignored by Git.

   | Variable | Purpose / example | Where to get it | Required? |
   |---|---|---|---|
   | `AZURE_TENANT_ID` | Entra tenant ID | Entra admin center, app registration overview | For SSO |
   | `AZURE_CLIENT_ID` | App/client ID | Entra app registration overview | For SSO |
   | `AZURE_CLIENT_SECRET` | Client secret value | Create under app registration Certificates & secrets; store securely and note expiry | For SSO |
   | `REDIRECT_URI` | `http://localhost:8080/auth/callback` locally | Must exactly match the URI in the Entra app registration; use this machine's approved address | For SSO |
   | `SESSION_SECRET` | Random 64-character hex string | Generated by setup script; or run the command below | Required and non-placeholder for SSO; use a long random value always |
   | `HTTPS_ONLY` | `false` locally, `true` behind HTTPS | Set for the deployment | Safe local default in example; enable in HTTPS production |
   | `SSO_ENABLED` | `false` local only; `true` real use | Set by the operator | Example is false; production must enable |
   | `DEV_USER_NAME` | Local development display name | Set by the operator | Safe default |
   | `DEV_USER_EMAIL` | Local development email identity | Set by the operator | Safe default |
   | `ENABLE_DIAG` | `false` or `true` for clipboard diagnostics | Set only for local diagnosis | Safe default false |
   | `DATABASE_URL` | `sqlite+aiosqlite:///./data/handover.db` | SQLite local; PostgreSQL URL from database administrator | Safe SQLite default |
   | `DOCUMENTS_DIR` | `./data/documents` | Set storage path if needed | Safe default |
   | `DOCUMENT_MAX_BYTES` | `10485760` (10 MiB) | Set by operator | Safe default |
   | `SNIPEIT_TIMEOUT_SECONDS` | `10` | Set by operator | Safe default |
   | `SNIPEIT_URL` | `http://localhost:8081` | Snipe-IT administrator | Optional for portal-only setup |
   | `SNIPEIT_TOKEN` | `<PASTE_VALUE_HERE>` | Create a dedicated Snipe-IT service account token | Optional; required for Snipe-IT connection |
   | `REQUIRED_SOFTWARE_IDS` | `forticlient,sccm,intune,office2021` | Snipe-IT/software configuration owner | Safe default |
   | `LOG_LEVEL` | `INFO` | Set by operator | Safe default |
   | `STALL_HOURS` | `24` | Set by process owner | Safe proposed default; `0` disables |
   | `RATE_LIMIT_WINDOW_SECONDS` | `60` | Set by operator | Safe default |
   | `RATE_LIMIT_SUBMIT_PER_WINDOW` | `60` | Set by operator | Safe default |
   | `RATE_LIMIT_RECIPIENT_SEARCH_PER_WINDOW` | `60` | Set by operator | Safe default |

   The code also reads `APP_HOST` (default `localhost:8080`) for the address embedded in the agent command, and `SESSION_TTL` (default `600` seconds) for the 10-minute code expiry. These are not in `.env.example`.

3. Generate a session secret manually only if you need to replace it.

   ```powershell
   .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_hex(32))"
   ```

   You should see a random value. Paste it into `.env` as `SESSION_SECRET`; never share it. With SSO enabled, an empty or `change-me` secret makes startup fail closed.

4. Choose the authentication mode. Local mode binds to loopback and uses a development identity; it is not for a shared computer or production. The UI shows a `DEV MODE` marker.

   ```powershell
   # Local development only; these values apply to this PowerShell session.
   $env:SSO_ENABLED = "false"
   $env:HTTPS_ONLY = "false"
   ```

   You should see no output. Real use requires `SSO_ENABLED=true`, a real secret, valid Entra IDs and secret, and an exact registered `REDIRECT_URI`. Ask the Entra administrator for the app registration and callback URI for this machine. Do not use the local bypass for shared access.

## Part 3: Install Snipe-IT (local development instance)

This development stack uses Docker Compose, MariaDB and Snipe-IT v8.8.3. Its credentials and data are for local development only.

1. Create the development environment file and random local passwords/key.

   ```powershell
   .\deploy\snipeit-dev\bootstrap.ps1
   ```

   This script creates `.env` files, starts Docker, seeds test data, and writes the Snipe-IT token to the ignored portal `.env` without printing the token. In this run it could not run because Docker Engine access was denied; all Docker-dependent steps here are **NOT VERIFIED**.

2. Confirm the services after Docker is available.

   ```powershell
   Set-Location .\deploy\snipeit-dev
   docker compose ps
   ```

   You should see `snipeit` and `snipeit-db` running. Wait for the Snipe-IT login page at `http://localhost:8081`.

3. Sign in to the development instance using `admin` (email `admin@example.test`) and password `ChangeMe-Dev-Only-1`. These are public development credentials; immediately change them on any shared machine. Never use them outside this local throwaway instance.

4. The bootstrap generates and configures the Snipe-IT `SNIPEIT_APP_KEY`, database passwords, Passport keys and permissions. Manual setup details are in `deploy/snipeit-dev/README.md`. Do not run `docker compose down -v` unless you intend to erase the database and uploads.

5. The bootstrap creates the `TEST-recipient` user and `TEST-SN-0001` asset, then creates a local API token. Its manual alternative is **Admin → API keys → Create New**. Use only `TEST-` fixtures.

6. Confirm the portal `.env` has `SNIPEIT_URL=http://localhost:8081` and `SNIPEIT_TOKEN=<PASTE_VALUE_HERE>` (the actual token is written by bootstrap). Restart the portal after changing `.env`.

### Use your real Snipe-IT instead

Set `SNIPEIT_URL` to the approved Snipe-IT base URL and `SNIPEIT_TOKEN` to a dedicated service-account token. Grant only the API permissions required for `GET /api/v1/users/me`, user and asset searches/reads, asset checkout/checkin, and asset file upload. Snipe-IT's role controls may not split all these actions into narrower permissions; have its administrator verify the narrowest available role. Review [verified API details](../snipeit-api-verified.md). Do not use an administrator's personal token. Test with a `TEST-` asset first. Attribution follows the token owner; see owner decision D-12/Q-13 before choosing a production credential policy.

## Part 4: Start and check

1. Start the portal for this PC only.

   ```powershell
   .\scripts\start.ps1
   ```

   It binds to `127.0.0.1:8080`, with SSO disabled for local development. Keep this PowerShell window open. You should see Uvicorn start without an error.

2. Open `http://localhost:8080/` and `http://localhost:8080/handovers`.

   You should see the Handover Portal and its handover dashboard.

3. Check portal liveness in another PowerShell window.

   ```powershell
   Invoke-RestMethod http://localhost:8080/api/health
   ```

   You should see `status : ok`.

4. After configuring Snipe-IT and signing in, check `http://localhost:8080/api/snipeit/health` in the browser. You should see `connected: true`. **NOT VERIFIED** without Docker Engine and a configured token.

5. Create one handover using only `TEST-SN-0001`, then cancel it from the detail page. You should see its status change to Cancelled. **NOT VERIFIED** in this run.

## Part 5: Use it from another device

1. Set `APP_HOST` in the root `.env` to the portal's reachable DNS name or IP and port, for example `192.168.1.50:8080`. The agent command uses this setting. Do not use `localhost` when the employee's PC is different from the portal PC.

2. If the employee device must connect, start the portal bound to all interfaces.

   ```powershell
   .\scripts\start.ps1 -HostAddress 0.0.0.0
   ```

   This makes the service reachable on network interfaces; it increases exposure. Use only an approved trusted internal network and firewall scope.

3. Ask an administrator to allow inbound TCP 8080 on the Windows Defender Firewall for the internal network profile and approved subnet only. Do not create a public profile rule. Firewall configuration is **NOT VERIFIED** here.

4. Production requires a reverse proxy with TLS, `HTTPS_ONLY=true`, `SSO_ENABLED=true`, an exact Entra `REDIRECT_URI`, and an approved public/base address. Do not expose plain HTTP to the internet. The one-time agent session code expires after 10 minutes.

## Part 7: Backups and updates

1. Stop the portal with Ctrl+C, then copy `data\handover.db` and the `data\documents` folder to approved protected storage. They contain personal and handover data. Do not copy `.env` into an unprotected backup.

2. Update the code and database.

   ```powershell
   git pull
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe -m alembic upgrade head
   ```

   You should see Git update output, pip report installed requirements, and Alembic report migrations complete or already current.

PostgreSQL is supported through `DATABASE_URL`, but a clean production PostgreSQL installation and migration is **NOT VERIFIED** in this guide run. SQLite is the local default at `data/handover.db`.

## Part 8: Uninstall / reset

1. Stop the portal with Ctrl+C.
2. To remove only the local Snipe-IT containers and preserve their data, run `docker compose down` from `deploy\snipeit-dev`.
3. To erase Snipe-IT database and uploads, run `docker compose down -v` from `deploy\snipeit-dev`, then rerun `bootstrap.ps1`. **This deletes all Snipe-IT development data.**
4. To reset the portal's local data, stop the portal and remove `data\handover.db` and `data\documents` only after making any required backup.
5. Remove `.venv`, `.env`, and `deploy\snipeit-dev\.env` when uninstalling. Do not delete or share them before deciding whether their secrets need rotation.
